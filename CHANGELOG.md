# Changelog

All notable changes to CohortBuy. Format follows [Keep a Changelog](https://keepachangelog.com/).
Update the `[Unreleased]` section with **every** feature (see `CLAUDE.md` → "Keeping docs current").

## [Unreleased]

### Changed
- **UI consistency pass + professional forms** — promoted the cohort page's patterns into shared primitives (`ui/Modal`, `ui/IconButton`, `ui/Stepper`, `ui/Field` exporting `fieldClass`/`labelClass`/`subtleBtnClass` + `Field`/`Textarea`/`Select`) so the project and cohort pages now look identical. The project hero action bar now uses the same round **IconButtons** (Info · Share · Edit) + primary **Join** + **More** menu (Leave) as the cohort header. **Add Project is now a 3-step wizard** (Basics → Details → Access) matching the create-cohort wizard, Edit Project is a clean labeled modal, and the project page's inline forms/buttons use the shared field + button styles. Fixed a checkbox accent class (`accent-primary`).
- **Edit cohort: full field coverage + polished create form** — the cohort settings modal now also edits **cohort type**, **city/state**, and **coverage ZIP codes** (in addition to name/tagline/description/tags/images/join-questions); `UpdateCohortProfileInput` + `updateCohortProfile` gained `kind`/`city`/`region`/`coverageZips`, and `ZipCoverageField` got an `onChange` for the JS-driven modal. The **create cohort** form is now a 3-step **wizard** (Basics → Type & tags → Location & coverage) with a progress stepper and Back/Next/Create; all fields stay in one form so it still submits in a single action, Basics is validated before advancing, and Enter advances instead of submitting mid-wizard. No migration needed.

### Fixed
- **Search + location compose** — search now filters *within* the active location scope (your ZIP by default) instead of either being blocked by it or ignoring it. When a local search/tag has no matches, the empty state offers a one-click "Search all of <country>" to widen (preserving the query); in the all-locations view, local matches are still surfaced first and badged. "Your cohorts" is narrowed by the query too.
- **Edit cohort form labels** — the Name, Tagline, and Description fields in the cohort settings modal had only placeholders (which disappear on input and aren't accessible); each now has a proper `<label>` (with `htmlFor`/`id`), and the dynamic join-question inputs got `aria-label`s.

### Changed
- **Cards get an image banner back + your cohorts shown first** — `CohortCard` now has a compact image banner (cover or brand gradient) with the avatar, name, and location **overlaid** (legible via a dark gradient) so it's never an empty banner, then tagline/tags/metrics below. The separate "Your cohorts" chip strip is gone — your cohorts now render **first, as full cards with a status badge** (Manager/Member/Pending) via a new `my_cohort_cards()` RPC (`getMyCohortCards`, `MyCohortCard`), and are de-duplicated from the discovery results. The hero is shorter/banner-like (less height, tighter copy). Migration `20260617180000_my_cohort_cards.sql`.
- **Discover hero (Zillow-style)** — the discover page now opens with a full-width image hero (`public/hero-cohorts.jpg`, dark gradient overlay, brand-green fallback) carrying a bold headline ("Group buying for your neighborhood") and a large, prominent ZIP search (`SetZipForm` `variant="hero"`). Scope state + widen toggle sit in the hero; "Create cohort" moved to the discover section header. Swap `public/hero-cohorts.jpg` to change the photo.
- **Discover page redesign (purpose-forward)** — replaced the bland title + large empty location card with a brand-tinted **hero** that states the value ("Find a cohort near you — pool with neighbors…") and folds in the ZIP/location control with scope-aware copy. `CohortCard` reworked to be **content-first** (avatar + name + location, tagline, tags, metrics) so it reads well without a cover image (no more empty banners). "Your cohorts" condensed to compact chips; empty state is now a friendly dashed card with a Create CTA.
- **Discovery is country-bounded** — the broadest discovery view is now "all of your country", never worldwide. The widen toggle reads "Browse all of <country>" (was "Show all locations"); cross-country cohorts no longer appear for a viewer who has a country on file. (Worldwide only as a fallback when no country is set.)

### Added
- **OpenAI provider support** — the LLM client now dispatches on provider: `openai` (Chat Completions + function calling) or `anthropic` (Messages). `resolveModel` gained an **env override** (`AI_DEFAULT_PROVIDER` / `AI_DEFAULT_MODEL`) so you can switch providers without a DB row — e.g. `OPENAI_API_KEY` + `AI_DEFAULT_PROVIDER=openai` + `AI_DEFAULT_MODEL=gpt-4o`. The advisor passes the resolved provider through; the `propose_project` tool maps to OpenAI function-calling automatically. SETUP §2 documents both paths.
- **Project Advisor — first AI feature (Addendum F, Stage 0)** — a conversational front door at `/<cohort>/advisor` (managers; "Advisor" button by Add Project). It understands a half-formed intent, **validates fit** (qualifier, not a yes-machine), shapes the idea, and hands off a **pre-filled project setup** via a `propose_project` tool — which drops straight into an editable confirmation form that creates the project. System prompt enforces the Addendum F **pacing** rules (one question at a time, no re-summarizing, profile presented once). New `core/ai/llm.ts` (minimal Anthropic Messages client, server-only, key from `ANTHROPIC_API_KEY`), `core/advisor` slice (domain + `advise` service using `resolveModel`), `/api/advisor` route, `AdvisorChat` UI. Degrades gracefully with a friendly notice if no API key is set.
- **Project profile / setup (Addendum E, Phase 1)** — project setup now captures a real **profile**: `project_type` (service vs group-buy), `service_scope` (service / equipment / both), `split_method` (even / by-quantity / by-usage / custom), plus **min group size** and **join deadline** (columns existed, now set at setup). The Add Project flow is a richer **4-step wizard** (Basics → Type & scope → Timing & size → Access), the cohort's `kind` seeds the project-type default, and the profile shows in the project Details panel. `create_service_request` extended with the profile params. Sets up the future configurable-lifecycle state machine (contract structure + payment mode stay deferred per D). Migration `20260617220000_project_profile.sql`.
- **Contract & payment structure (Addendum D)** — projects now carry two independent, coordinator/manager-set flags surfaced in **Decision & contract**: **contract structure** (individual per-member vs one combined group contract) and **payment mode** (each member pays the vendor directly, off-platform vs pooled escrow). Negotiation stays collective; only the back-half structure branches. Launch posture is no-money: defaults are `individual` + `individual_direct`, and **pooled escrow is shown as "coming later"** (a deferred opt-in). New `service_requests.contract_structure`/`payment_mode`, coordinator-gated `set_project_terms` RPC, `setProjectTerms` service + `setTermsAction`. Migration `20260617210000_project_terms.sql`.
- **Project action bar (Info · Share · Edit · Join · Exit) + coordinator lock** — the project hero now carries a full action bar. **Info** opens an at-a-glance About modal (cohort, participants, started/target, scope count, price, description, driver); **Share** copies the link; **Edit** shows for the coordinator or a cohort manager; **Join** is offered only to cohort members while the project is still open (early stages, not locked) and not already joined; **Exit** lets a non-coordinator participant leave (with confirm) unless the project is locked. New **`service_requests.locked`** flag — the coordinator can freeze joining *and* leaving at creation or in Edit (e.g. once a quote is selected); joining also auto-closes after the quoting stage (`JOINABLE_STATUSES`). Server-side gating in `joinServiceRequest`/`leaveProject` (locked/stage/coordinator checks), new `leaveProjectAction`, `ProjectHeaderActions` component, and a "Locked" pill on the hero. Migration `20260617200000_project_lock.sql`.
- **Project hero + start/target dates** — the project detail page now opens with a banner hero (brand gradient, category-matched icon tile, stage badge) mirroring the cohort page, a meta row (started date, target date with an "in Nd / Nd overdue" hint, participant count), and a four-up stat strip (stage, participants, target date, agreed/best price). New `service_requests.target_date`, settable on the Add- and Edit-project forms and passed through `create_service_request(p_target)`; shown in the side Details panel and seeded across the demo projects. Migration `20260617190000_project_target.sql`.
- **Local cohorts by ZIP coverage** — cohorts are now genuinely local: each declares a **coverage area** as a list of US ZIP codes (`cohorts.coverage_zips text[]`, GIN-indexed, + `city`/`region`), entered on the create form via a new `ZipCoverageField` (add several neighborhoods). People match by **their ZIP**: profiles gain `postal_code`/`city`, set via a `SetZipForm` on discovery (`saveMyLocation` → `setMyLocation` service). Discovery is **ZIP-scoped, local-first** — `discover_cohorts` gains `p_zip`/`p_scope` ('zip' = cohorts covering your ZIP, 'country', 'all') and returns a `covers` flag (cards show a "Serves your area" badge in wider views) plus `city`/`region`. `create_cohort` takes `p_coverage_zips`/`p_city`/`p_region`. New domain: `Zip`/`ZipList`, `SetLocationInput`; cohort `city`/`region`/`coverage_zips`. Cards show city/region instead of country. Seed: demo cohorts get Austin-area ZIPs and the demo operator's profile is set to 78704 so local discovery works immediately. Migration `20260617170000_cohort_coverage.sql`. (Supersedes the country-only filter from `20260617160000`; browser-geolocation→ZIP is a future add since it needs reverse geocoding.)

### Changed
- **Decluttered + location-aware discovery** — the discover page now defaults to the **viewer's country** (other countries hidden) with a "Show all locations" toggle, via a new `p_filter_country` arg on `discover_cohorts`. The tag filter only lists tags that **actually appear** in the current results (not the whole catalog) and collapses to one row with a "+ more" expander (new `TagFilter` component). Removed the redundant inline name search (header search covers it), and the "Near you" badge now only shows in the all-locations view (it's redundant when results are already country-scoped). Migration `20260617160000_discover_country_filter.sql`.

### Added
- **Cohort tags (multi) + platform tag catalog** — cohorts now carry multiple **tags** instead of a single category. New `cohorts.tags text[]` (GIN-indexed; existing `category` slugified into it and the column retired from the app), and a staff-managed **`tag_catalog`** table (RLS: all read, staff write) seeded with ~30 common tags (fencing, solar, pest-control, mulch-compost, ev-chargers, hoa, …). `create_cohort` takes `p_tags`; `discover_cohorts` returns `tags` and gains a `p_tag` filter. New `TagPicker` (pick common tags or add custom, slugified/deduped, ≤10) used on the **create** form and the **edit** modal; cards show tag chips; the discover page has a **clickable tag filter** (`?tag=slug`, preserves search). Domain adds `TagList`/`TagSlug`/`slugifyTag`/`humanizeTag`/`TagCatalogItem`; `getTagCatalog` service. Migration `20260617150000_cohort_tags.sql`.
- **Cohort type — Service vs Group buy** — cohorts now carry a `kind` (`service` = work quoted & done per home; `group_buy` = shared volume product order). `cohorts.kind` column (default `service`), `create_cohort`/`discover_cohorts` updated to set/return it, `CohortKind` + `COHORT_KIND_LABELS` in the domain, and a **Cohort type** selector on the create form. The discover page renders distinct **"Services"** and **"Group buys"** sections (each ordered near-you first), and each card shows its type in the meta line. Demo seed updated with 4 group-buy cohorts (mulch, firewood, propane, EV chargers). Migration `20260617140000_cohort_kind.sql`.
- **Marketplace-style cohort discovery** — `/cohorts` now reads from a new `discover_cohorts(p_query, p_country, p_limit)` `SECURITY DEFINER` RPC that returns each public cohort with aggregates — **member count**, **projects**, and **value coordinated** (sum of `service_requests.agreed_amount_cents`) — and a **near-you** flag (cohort country = viewer's profile country). Results are ordered near-first, then by members → value → recency, and split into **"Near you"** and **"Popular cohorts"** sections (a single "Results" grid when searching). `CohortCard` redesigned with trust/value signals (members · $ coordinated · projects, "Near you" badge, category, avatar/cover). New `discoverCohorts` service + `discover` repo + `PublicCohortCard`/`DiscoverCohortsInput` domain; `searchPublicCohorts` retained for the agent tool. Migration `20260617130000_discover_cohorts.sql`. Note: `value_cents` is treated as USD-equivalent (mixes currencies if a cohort ever spans them) — fine for the US-first launch.
- **Global header search** — a search box in the app header (`HeaderSearch`, plain GET form to `/cohorts`, works without JS) lets members search from anywhere. Placeholder is forward-looking ("Search cohorts, services, products…"); scope is cohort name today, with services/products planned. Header reflows mobile-first: logo shrinks to the mark, search takes the flexible middle, theme + profile stay pinned right.
- **Public cohort discovery as promotional cards** — `/cohorts` now renders "Discover public cohorts" as a responsive card grid (`CohortCard`: cover image or brand gradient, avatar, name, tagline, 2-line description, category badge, handle) instead of a flat list, mirroring a marketplace browse experience. Page widened to `max-w-5xl` for a 1→2→3-column grid. Tokens only; theme-aware.
- **Google sign-in** — "Continue with Google" on `/login` (`signInWithOAuth`, returns via the existing `/auth/callback`); gives a login path that doesn't depend on email delivery. SETUP.md documents enabling the Supabase Google provider + redirect URLs, and clarifies that magic-link login requires custom SMTP (Resend) — the missing SMTP is the cause of the "session keeps dropping to /login" symptom (the email never arrives).
- **Platform admin panel** — `/admin` (staff/admin only) with an operations overview: KPI cards (cohorts, approved members, projects, completed, waitlist, total value coordinated), projects-by-stage breakdown, recent project activity, and inactive-cohort flags (30d+). Backed by `is_platform_staff()`-gated `SECURITY DEFINER` RPCs (`admin_overview`, `admin_recent_projects`, `admin_inactive_cohorts`) in a new `core/admin` slice. Staff-only "Platform admin" link added to the user menu. Migration `20260617120000_admin_overview.sql`.
- **Edit project** — coordinator/manager can edit a project's title, category, description and driver from a modal on the project page (`editProject` service, RLS-gated; `EditProjectButton`).
- **Demo seed for the discover page** — `supabase/seeds/demo_discover.sql`: a pool of 40 demo neighbors and 12 `[public]` cohorts across the plan's service categories (Fencing, Solar, Roofing, Landscaping, Pest Control) plus neighbor group-buy types (Driveway/Paving, Gutters, HVAC, Exterior Painting, Tree Service, Fiber), with varied member counts, countries (US near-you + GB/CA/IN/AU), and projects carrying agreed amounts so cards show real members · $ coordinated · projects. Idempotent; run manually against a dev DB. Requires `20260617130000_discover_cohorts.sql`.
- **Demo seed for cohort SA** — `supabase/seeds/demo_sa.sql`: six `[DEMO]` projects spanning the lifecycle (forming → rfq → deciding → contracting → funding → completed) with vendors, quotes, scope, discussion and cost shares, plus four demo members. Idempotent; run manually against a dev DB.
- **Procurement lifecycle — decision → contract → cost-share → deliver** — the coordinator can **select a winning quote** (marks it `selected`, others `rejected`, records agreed amount + vendor on the project); **record the off-platform contract reference** (Google Drive link + note) with a facilitator disclaimer that the agreement is directly between members and the vendor; **generate an even split** of the agreed amount across joined participants (remainder cents to the coordinator) into a **`cost_shares`** tracker with per-member **paid/unpaid** toggle (coordinator or the member themselves) and a "collected of agreed" total — **tracking only, payments settle off-platform, the platform never holds funds**; and **sign off completion** with a note + date (shows a Completed banner). All mutations run through coordinator-gated `SECURITY DEFINER` RPCs (`select_quote`, `set_contract`, `generate_cost_shares`, `set_share_paid`, `complete_project`); names exposed via `cost_shares_feed`. `SafetyNote` reused in the cost-share section. Migration `20260617000000_lifecycle.sql`.
- **Rich project detail page** — redesigned `/requests/[id]` into authentic, scannable sections: header (status badge, category, start month, participant count), progress (stage bar + advance control), **About this project** with a distinct **"Why now — the driver"** block, **Scope**, **Vendors & quotes** (vendor count summary, lowest-price flagged "Best price"), **Discussion** (threaded comments = correspondence, with avatars/names/relative time), and a side rail of **Details** + **Participants**. Adds `service_requests.driver` and a `request_comments` table (RLS: cohort members read, own-row insert) with a `request_comments_feed` SECURITY DEFINER fn exposing author names. New `addComment`/`listComments` service + `addCommentAction`; `create_service_request` now takes `p_driver`; Add-project form captures the driver. Migration `20260616230000_project_detail.sql`.
- **Landing page** — Next.js 14 (App Router, TS) + Tailwind; hero, chat mockup, how-it-works, waitlist.
- **Waitlist** — Supabase-backed signup; reused across UI form, `/api/waitlist` route, and `join_waitlist` tool.
- **Supabase CLI migrations** — schema managed as migrations under `supabase/migrations/`.
- **Hero image slot** — Next/Image with swappable local/remote photo.
- **Design system** — semantic light/dark tokens, `darkMode: class`, no-flash theme script, mobile theme-color; UI primitives (`Button`, `Input`, `Checkbox`); `ThemeToggle`; 44px touch targets.
- **Modular core architecture** — `src/core/` layered as domain (Zod) → repositories → services → tools registry, with shared `Ctx`/`Result`. Entry points (UI, API, agent, MCP) reuse the same services.
- **Notifications** — multi-channel `NotificationChannel` adapter (console now → providers later); consent-aware `notifyActionDue`; `profiles` + `notifications` tables.
- **AI configuration** — per-cohort model override + global default (`resolveModel`, admin-gated set); `ai_settings` / `cohort_ai_settings`.
- **Agent memory** — cohort- and work-item-scoped memory (`recordMemory` / `recallMemory`); `agent_memory` table.
- **In-app tokens (Web2)** — non-cash points ledger (`token_accounts` / `token_transactions` + atomic `apply_token_tx` RPC); earn rules, admin grant, spend (overspend-blocked), balance + status tier.
- **Quotes** — record vendor quotes against a project (`quotes`, money as integer minor units + ISO currency, RLS); sorted price comparison with `Intl.NumberFormat`. UI on `/requests/[id]`: record-a-quote form + comparison list. Tool: add quote.
- **Scope + stage transitions** — members add scope items to a project (`scope_items`, RLS); coordinator/manager can **advance the project through its stages** (`advanceStatus`). UI on `/requests/[id]`: scope list + add form, and an "Advance to <next stage>" control. Tools: add scope item, advance request status.
- **Service requests (projects)** — cohort members start projects with a lifecycle status (`forming → … → completed`); creator becomes coordinator (`create_service_request` RPC, member-gated); participants can join; cohort-scoped RLS. UI: projects list + "Start a project" on the cohort page, `/requests/[id]` detail with stage bar, participants, and join. Tools: create/join service request.
- **Post actions menu + Add-project button** — each post has a **⋯ menu** (Edit · Make public/members · Delete) for the author/admins (replaces the inline toggle). The Projects card now has an **"Add project"** button (managers/co-admins) opening a modal, instead of an always-expanded form.
- **Per-post visibility** — posts default to **members-only**; admins/co-admins (or the author) can set a post to **public** so non-members can see it. Composer has a visibility selector; each post shows a Members/Public badge with a toggle; the feed hides member-only posts from non-members.
- **Join screening + ask-info loop** — cohort admins define **join questions** (with optional expected answers) in settings; requestors answer them in a join modal that carries a prominent **safety note** (never share SSN/OTP/passwords; CohortBuy never asks; report misuse to helpline@cohortbuy.com). Admins see the answers and can **approve / reject / ask for more info**; "ask for info" notifies the requestor, who responds inline, and it returns to the queue. (Secret join-code gating deferred — needs leak-safe handling.)
- **Join requests show names** — managers now see the requester's name (and note) in pending join requests, via a `SECURITY DEFINER` function (was a truncated user id, since profile privacy hides names).
- **Login entry** — clear, always-visible "Log in" button on the landing header → `/login`.
- **Polished icons (lucide-react)** — replaced hand-drawn SVGs with the lucide icon set across the banner action bar (Info/Share/Edit/More), theme toggle (Sun/Moon), profile menu, and post composer for a crisp, modern look.
- **Banner actions + cover image** — LinkedIn-style action bar on the cohort banner: **Info** (About-this-cohort modal: description + details), **Share** (copy link), **Edit** (managers — settings modal with **cover + logo image upload**, name/tagline/description), and **More** (copy link, About, **Leave cohort** for non-owners). Cohort **cover image** (uploaded, auto-fits the banner, with size guidelines) + `leave_cohort` function.
- **Image upload + composer reset** — post composer is now a client component: attach an image (uploaded to the `cohort-media` Supabase Storage bucket, 5MB cap), see status, and the form **clears after posting**. Storage bucket + RLS policies added by migration.
- **Staff/admin RLS** — `is_platform_staff()` helper + read policies so platform staff/admin can see all data (for the admin panel); staff can manage AI config + agent memory.
- **Post errors surfaced** — failed posts now redirect with a visible reason instead of failing silently.
- **Cohort group page (LinkedIn-style) + posts feed** — redesigned `/[handle]` as a community page: cover banner + avatar identity header, two-column layout (post feed + projects in the main column, members + manage rails on the side). Admins/co-admins can **post updates** (text + optional image) to a cohort feed (`cohort_posts`, RLS; author-resolving feed function). Tool: create cohort post.
- **Cohort profile + members directory** — cohort header with logo/avatar, slogan (tagline), and "Est. <year> · N members"; a **members directory** (name, role Owner/Co-admin/Member, title, member-since, **online status** via presence heartbeat). Owner can **promote co-admins**; managers **assign titles** (e.g. Treasurer) and **edit cohort settings** (name/tagline/logo/description). Presence: `/api/presence` heartbeat updates `last_seen_at`. (Members directory via `SECURITY DEFINER` function so co-members see each other despite profile RLS.)
- **Dashboard** — post-login home (`/dashboard`): active projects with **progress bars + stage**, recent activity (notifications), tokens, your cohorts, and quick actions. Login/onboarding now land here; nav + profile menu link to it. Join-approval now generates a real notification (service-role) so the activity feed populates.
- **App shell + profile management** — sticky top nav (logo, Cohorts, theme toggle) with a **profile dropdown menu** (account, edit profile, sign out) across signed-in pages; editable **`/account/profile`** page; shared sign-out action.
- **Cohorts + membership** — public/private cohorts with vanity handles; request → manager **approve / reject / ask-info** flow; cohort-keyed RLS via `SECURITY DEFINER` helpers (`auth_cohort_ids`, `auth_is_cohort_manager`) + `create_cohort` RPC. UI: `/cohorts` (search public + my cohorts), `/cohorts/new`, `/[handle]` (request to join + manager review). Tools: create/request/review/search.
- **Auth + profiles + onboarding** — Supabase Auth (magic link) via `@supabase/ssr` (server/browser clients + session middleware); `/login`, `/auth/callback`, `/onboarding` (captures name, phone, SMS opt-in, preferred channel, country), `/account` (profile + token balance/tier + sign out). Profile auto-created on signup (trigger); self-access RLS on profiles/tokens/notifications.
- **Docs** — `CHANGELOG.md`, `TESTING_PLAN.md`, and `SETUP.md` (integration/setup guide for Supabase, AI, Resend, Twilio, Google, etc.); expanded `.env.example`.
