## [Unreleased]

### Security
- **Audit log** — append-only `audit_log` records sensitive actions (PII reveal in admin, self data export, account closure). Writes via `record_audit()`, reads via staff-gated `admin_audit_log()` — both SECURITY DEFINER, no direct table access — surfaced as an "Audit log" section on `/admin`. `core/audit` slice + `logAudit`/`getAuditLog`. Migration `20260618160000_audit_log.sql`.
- **Member data rights (export + delete)** — account page now has **Download your data** (`export_my_data()` → `/api/account/export`, full JSON of the member's own profile/projects/scope/orders/tokens) and **Delete your account** (`request_account_deletion()`: scrubs name/email/phone/avatar/handle, marks deleted, removes memberships, signs out; blocks if you coordinate an in-flight project). Shared project records are **anonymized, not destroyed**, so other members' data stays intact. Both audited. Migration `20260618170000_account_data.sql`. (Honest gap: full `auth.users` erasure is an ops step.)
- **Least-privilege admin access** — removed the blanket platform-staff `SELECT` policies on private user-content tables (profiles, cohort_members, scope_items, quotes, cohort_posts, token_accounts/transactions, notifications, service_requests, request_participants, cohorts). The admin panel is unaffected — it reads through curated security-definer RPCs (`admin_*`, `platform_public_stats`) — but admins can no longer pull raw private rows (phones, message payloads, scope, quotes, token ledgers) directly via the API. AI-config/memory staff policies kept (admin features). Migration `20260618150000_least_privilege_admin.sql`.
- **PII masking in admin UI** — emails and phone numbers in the admin inbox are masked by default (`MaskedValue`) and revealed only on explicit click.
- **Admin data-access policy** — documented least-privilege, PII minimisation, purpose limitation, consent boundaries, and the deferred audit-log/retention items in `Legal_Terms_and_Liability_Notes.md`.

- **"For vendors" page + get-listed (acquisition)** — a public `/vendors` page selling the promotion-channel pitch (pre-aggregated demand, quote-once-serve-many, standardized RFQs, get found/featured), a how-it-works, the live public stats band, and a **get-listed lead form** capturing inbound vendors to a new `vendor_leads` table (anon insert, mirrors the waitlist pattern). Landing's "For vendors" nav + section now link here. Migration `20260618130000_vendor_leads.sql`.
- **Landing refresh for residents (acquisition)** — the public homepage now leads with **savings**, not the agent: hero reframed ("Stop overpaying. Buy with your block."), with a primary **"Find a cohort near you"** CTA into the product alongside the waitlist. Added a **live social-proof band** pulling real aggregate numbers from public cohorts (cohorts, group projects, value facilitated, saved-together) via a new anon-safe `platform_public_stats()` RPC (`getPublicStats`) — falls back to the qualitative strip when there's no data yet. Added a **"For vendors"** section + nav link positioning CohortBuy as a promotion channel (pre-aggregated demand, RFQs, get-listed CTA). Migration `20260618110000_public_stats.sql`.
- **Group-buy suppliers & competitive bids** — group buys can now source and compare sellers, reusing the service-side machinery in the short track (no extra stages). The Research tab gained a **Suppliers & bids** panel: add candidate **suppliers** by free-text or **pick from the ops vendor registry** (`addRegistryCandidate` / `listRegistryVendors`), or **Suggest with AI**; record each one's **competitive bid** (price/terms via the quote wizard) and **Select as supplier** (sets the project's recorded vendor). Funding still bills from member orders; the winning bid informs the coordinator's per-option prices. Reuses `vendor_candidates`, `quotes`/select-winner and the `vendors` registry — no new tables.
- **Group-buy variants + per-member orders (multiple units / configs)** — a group buy can now offer several **options** (variants — e.g. different configs/sizes), each with its own negotiated unit price, and each member places a **per-variant order quantity**. The "Product & deal" panel gained an **Options & pricing** catalog (coordinator adds/edits/deletes options + sets each price; everyone sees price, committed quantity and line total), a per-member **Your qty** input on each priced option, and a **deal totals** row (your order total, group total, buyers, total units). Funding now **bills by line** — each member is charged `Σ quantity × unit price` (new `Bill from orders` action / `generate_group_buy_shares`) instead of an even split, and the project total syncs to the sum. New `group_buy_variants` + `group_buy_orders` tables with RLS, `set_group_buy_variant` / `delete_group_buy_variant` / `set_my_order` / `generate_group_buy_shares` RPCs, and a `core/groupbuy` slice. Migration `20260618100000_group_buy_variants.sql`. (Quantities are editable in Forming/Research and lock at Funding. Volume tier-ladder pricing is still a future add.)
- **Group-buy Research → "Product & deal"** — the group-buy Research phase is no longer just a price box. It now walks the coordinator through three steps: (1) **Product spec** — capture name, specs, link and image, either by hand or by **pasting a product page → AI extract** (`ProductWizard` → `/api/extract-product` → `extractProduct`); (2) **Market price (reference)** — an **Estimate with AI** button returns a typical per-unit retail range with its assumptions (`estimateProductPrice`), honestly labeled as a from-knowledge estimate to verify against the live seller (no web access yet); (3) **Negotiated group price** — the coordinator records the secured price, and the panel shows **"save ~$X vs retail"** against the reference. New `product_name/url/specs/image_url` columns + `set_product_info` RPC (migration `20260618090000_group_buy_product.sql`); reference range reuses `benchmark_*`, negotiated price reuses `agreed_*`. Future upgrade path: swap the AI estimate for live web-search pricing in the same slot, and add the volume tier-ladder / countdown (Addenda A–C).
